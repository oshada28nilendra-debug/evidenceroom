# EvidenceRoom release design

A local-first CLI takes a research question, competing options and sources. Sources are local UTF-8 text/HTML files or explicit HTTPS URLs. A real model can propose verifiable claims and annotate retrieved passages. Offline mode is deterministic retrieval only, clearly marked as not AI reasoning. Users can supply claims to keep their wording fixed.

A lexical BM25 retriever provides bounded paragraphs per claim. A model emits support/oppose/context/inference annotations against passage IDs; deterministic code requires exact substring quotes, computes offsets against an immutable normalized-text snapshot and rejects unknown IDs, invented quotes or malformed records. Nothing executes source/model content. Source links/hashes, duplicate content/publisher warnings, source-type declarations, temporal caveats and unresolved opposing annotations are exported. No model-origin annotation is human-reviewed by default. A separate review command records accept/reject decisions bound to a bundle digest. Report HTML escapes all text and has no scripts/external assets; JSON is the canonical interchange.

Architecture: validation/storage models; safe HTTPS transport; source ingestion + Crossref discovery; lexical retrieval; compatible provider; bounded orchestration; deterministic renderer/review CLI. One sequential workflow, not multiple agents: there is no evidence that a swarm improves this slice. Alternative full crawler is rejected for scope and SSRF complexity; a report-only chatbot is rejected for weak inspectability.

Limits: Python >=3.11 stdlib runtime; 12 sources, 8 claims, 40,000 normalized characters/source, 160,000 total source characters; source fetch <=512 KB; 3 passages/claim, each <=1600 characters; 1 planning + at most 8 model calls; 120-second request timeout maximum; <=2048 completion tokens/call; no automatic retries or paid calls. Remote model requires HTTPS and explicit consent. Fetching requires explicit network consent and exact hostname allowlist; no redirects, cookies, auth headers or local/private addresses.

Acceptance: reproducible source hashes/offsets, rejected fabricated citations, conflicting records visible, identical sources not counted independently, reviewed/unreviewed annotations visibly distinct, deterministic offline E2E and export; real HTTP serialization/failure tests; actual public fetch/discovery attempted separately. A live model is verified only after actual inference, never from a test double. Missing repo designation means ZIP delivery; preserve remaining batch slots.
